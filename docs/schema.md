
# InventoryFlow – Data Schema and Data Dictionary

## 1. Overview

InventoryFlow processes inventory opening balances and inventory transactions to calculate daily stock balances for each product and warehouse.

The pipeline uses CSV files as input and SQLite for persistent storage.

The system maintains source records, transformed inventory movements, daily balances, rejected records, and pipeline execution history.

## 2. Input Datasets

### 2.1 Opening Balances

File: `data/input/opening_balances.csv`

| Column | Data Type | Description |
|---|---|---|
| product_id | String | Product identifier |
| warehouse_id | String | Warehouse identifier |
| opening_date | Date (YYYY-MM-DD) | Date from which opening stock applies |
| opening_quantity | Numeric | Initial stock quantity; must be non-negative and finite |

**Primary Key:** `(product_id, warehouse_id)`

Each product and warehouse combination must have one opening balance.

### 2.2 Inventory Transactions

File: `data/input/inventory_transactions.csv`

| Column | Data Type | Description |
|---|---|---|
| transaction_id | String | Unique transaction identifier |
| transaction_date | Date (YYYY-MM-DD) | Date of inventory movement |
| product_id | String | Product identifier |
| transaction_type | String | RECEIPT, ISSUE, TRANSFER, or ADJUSTMENT |
| quantity | Numeric | Inventory movement quantity |
| warehouse_id | String | Warehouse for receipt, issue, or adjustment |
| source_warehouse_id | String | Source warehouse for transfers |
| destination_warehouse_id | String | Destination warehouse for transfers |

**Primary Key:** `transaction_id`

The transaction ID uniquely identifies each accepted transaction in the database.

## 3. Transaction Business Rules

| Transaction Type | Input Quantity | Stock Impact |
|---|---|---|
| RECEIPT | Positive | Adds quantity to warehouse stock |
| ISSUE | Positive | Subtracts quantity from warehouse stock |
| TRANSFER | Positive | Subtracts from source and adds to destination |
| ADJUSTMENT | Positive or negative, but nonzero | Applies the signed quantity as a stock correction |

### Additional Validation Rules

- Required fields must not be empty.
- Dates must follow the `YYYY-MM-DD` format.
- Numeric quantities must be finite values.
- Opening quantities must be non-negative.
- Receipt, issue, and transfer quantities must be positive.
- Adjustment quantities may be positive or negative but cannot be zero.
- Transfers require different source and destination warehouses.
- Receipt, issue, and adjustment records require a warehouse identifier.
- Product and warehouse references must exist in the available opening balance records.
- Transaction IDs must be unique within the incoming transaction data.

### Duplicate Transaction Handling

- Duplicate transaction IDs within incoming data are treated as invalid records.
- An identical transaction already stored in SQLite is treated as already present and is not inserted again.
- A transaction with an existing ID but different data raises a database conflict error.

A transaction dated before its product and warehouse opening date causes the balance calculation to fail rather than producing an invalid historical balance.

## 4. Processed Inventory Movements

Generated internally by `processor.py`.

| Column | Data Type | Description |
|---|---|---|
| movement_id | String | Unique movement identifier |
| transaction_id | String | Original transaction identifier |
| movement_date | Date | Date of movement |
| product_id | String | Product identifier |
| transaction_type | String | Original transaction type |
| warehouse_id | String | Warehouse affected |
| quantity_delta | Numeric | Signed change in inventory |
| source_file | String | Original input filename |
| source_row | Integer | Original CSV row number |

### Movement Processing

- RECEIPT creates a positive movement.
- ISSUE creates a negative movement.
- ADJUSTMENT retains its original positive or negative sign.
- TRANSFER creates two movements:
  - Negative movement for the source warehouse.
  - Positive movement for the destination warehouse.

For every valid transfer:

```text
Outgoing Quantity + Incoming Quantity = 0
```

## 5. Daily Inventory Balances

Generated by `balance_calculator.py`.

| Column | Data Type | Description |
|---|---|---|
| balance_date | Date | Date of calculated balance |
| product_id | String | Product identifier |
| warehouse_id | String | Warehouse identifier |
| initial_stock | Numeric | Original opening quantity |
| daily_movement | Numeric | Net movement during the day |
| closing_stock | Numeric | End-of-day inventory quantity |
| transaction_count | Integer | Number of inventory movements during the day |
| negative_stock | Boolean | Indicates whether closing stock is below zero |

**Primary Key:** `(balance_date, product_id, warehouse_id)`

### Balance Calculation

For each product and warehouse:

```text
Closing Stock = Previous Closing Stock + Daily Movement
```

For the first calculated date:

```text
Closing Stock = Opening Quantity + Daily Movement
```

The calculation starts on the opening date and continues through the last movement date.

Dates without transactions are included with zero daily movement.

The `transaction_count` field counts inventory movement records for that product, warehouse, and date. A transfer contributes one movement to each affected warehouse.

Negative stock is identified through the `negative_stock` field. It is flagged in the output rather than automatically rejected.

## 6. Rejected Records

Invalid input records are stored in the `rejected_records` database table.

| Field | Data Type | Description |
|---|---|---|
| reject_id | Integer | Unique rejected record identifier |
| run_id | String | Pipeline execution identifier |
| source_file | String | Original input filename |
| source_row | Integer | Original CSV row number |
| record_data | JSON | Original record stored as JSON data |
| error_reason | String | Reason for record rejection |

Examples of rejected data include:

- Missing required fields
- Invalid dates or quantities
- Duplicate transaction IDs
- Invalid transaction types
- Invalid product or warehouse references
- Duplicate opening balance keys

Rejected records are retained with their original values and validation reasons.

## 7. SQLite Database Schema

Database location: `data/output/inventoryflow.db`

The database contains the following tables.

| Table | Primary Key | Purpose |
|---|---|---|
| pipeline_runs | run_id | Tracks pipeline execution status and metrics |
| opening_balances | product_id, warehouse_id | Stores opening stock records |
| inventory_transactions | transaction_id | Stores accepted transaction history |
| inventory_movements | movement_id | Stores transformed stock movements |
| daily_balances | balance_date, product_id, warehouse_id | Stores calculated daily inventory balances |
| rejected_records | reject_id | Stores invalid input records |

### 7.1 pipeline_runs

Stores pipeline execution details.

| Column | SQLite Data Type | Description |
|---|---|---|
| run_id | TEXT | Unique pipeline execution ID |
| start_time | TEXT | Execution start timestamp |
| end_time | TEXT | Execution completion timestamp |
| status | TEXT | RUNNING, SUCCESS, or FAILED |
| input_count | INTEGER | Total input records |
| valid_count | INTEGER | Total valid records |
| rejected_count | INTEGER | Total rejected records |
| movement_count | INTEGER | Total generated movements |
| balance_count | INTEGER | Total daily balance records |
| error_message | TEXT | Error description when execution fails |

### 7.2 opening_balances

Stores accepted opening balance records.

| Column | SQLite Data Type |
|---|---|
| product_id | TEXT |
| warehouse_id | TEXT |
| opening_date | TEXT |
| opening_quantity | REAL |

Primary key: `(product_id, warehouse_id)`

Opening quantity has a non-negative database constraint.

### 7.3 inventory_transactions

Stores accepted source transactions.

| transaction_id | TEXT |

| product_id | TEXT |

Primary key: `transaction_id`

Stores transformed stock movements.

|---|---|
| movement_id | TEXT |

| movement_date | TEXT |

Primary key: `movement_id`

### 7.5 daily_balances

Stores calculated daily stock balances.

| Column | SQLite Data Type |

| balance_date | TEXT |

| warehouse_id | TEXT |

Stores invalid input records.

| Column | SQLite Data Type |
|---|---|

Primary key: `reject_id`

`reject_id` is automatically generated. `run_id` references the pipeline execution table. `record_data` contains serialized JSON.

## 8. Assumptions and Limitations

- Product and warehouse references are derived from valid opening balance records; separate master tables are not currently implemented.
- Inventory quantities are represented using numeric values.
- Opening balances are maintained at product and warehouse level.
- Transaction dates must not precede the opening date for the corresponding product and warehouse.
- Daily balances are calculated from the opening date through the last movement date.
- Negative stock is flagged rather than automatically rejected.
- The prototype uses a local SQLite database and is intended for single-user execution.
- Persistent backdated correction audit history is not currently implemented.
